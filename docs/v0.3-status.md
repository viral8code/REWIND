# REWIND v0.3 実装状況

更新日: 2026-09-30

v0.3 の設計を Rust の型検査器・bytecode VM・仮想 I/O Runtime に実装した。設計文書は [REWIND_v0.3.md](REWIND_v0.3.md)、次版の提案は [REWIND_v0.4.md](REWIND_v0.4.md) に置く。

## 実装した機能

| 項目 | 実装 |
| --- | --- |
| 型抽象 | 関数・struct・enum の型パラメーター、推論と明示指定、trait 宣言・具体型への impl・bound、重複・曖昧・orphan impl の拒否。 |
| 標準 trait | Eq.eq、Ord.cmp、Hash.hash、Display.display。基本型には標準実装を提供する。 |
| Map | 基本型の既存順序と、独自 Ord.cmp による順序。ユーザー型のキーは入れ子の値を含む不変 snapshot として保存する。循環キー・関数・リソースを含むキーは拒否する。 |
| enum と match | 位置・名前付き variant、match 文・式、wildcard・binding・literal・範囲・struct・List・Option・Result パターン、Bool guard、網羅性エラーと到達不能 arm 警告。 |
| 関数値 | 関数の引数・戻り値・クロージャー。let は値、var は可変 cell を捕捉し、関数終了後も保持する。Checkpoint は cell、frame、cleanup と実行位置を復元する。 |
| モジュール | pub fn/struct/enum/trait/const、別名・選択的 import、同名項目の別名による区別、依存順の一度だけの初期化、循環・ルート外パスの拒否。 |
| プロジェクト | rewind.toml、ローカル依存、rewind.lock のハッシュ検証、明示的な lock 更新。 |
| 実行環境 | Args.all、許可制 Env.get、Directory.entries、固定 Locale.current。観測カーソルを復元し、ディレクトリの Host 競合を publish 前に検出する。 |
| リソース | 構造化 FileError、panic、using、自動 close、defer クロージャー、スコープ終了・return・?・エラー時の LIFO cleanup。 |
| 開発ツール | fmt と --check、Markdown API 文書と /// コメント、assert_eq、test --filter、複数ファイル check、trace と --trace-json。 |

## プロジェクト設定

```toml
language = "0.3"
source_root = "src"
entry = "main.rw"

[dependencies]
utils = "vendor/utils"
```

`entry` は `source_root` からの相対パス、依存パスはプロジェクトルートからの相対パスである。`source_root = "."` も使える。上記の依存は `import utils.module;` で `vendor/utils/module.rw` を読む。

```sh
rewind check --root /path/to/project
rewind run --root /path/to/project --locale ja-JP --allow-env CONFIG -- alpha beta
rewind test --root /path/to/project --filter counter
rewind lock --root /path/to/project
rewind fmt src/main.rw --check
rewind doc src/main.rw --root /path/to/project --output API.md
rewind trace src/main.rw --root /path/to/project --trace-json
```

## v0.3 の具体的な規則

- manifest が `language = "0.3"` の場合に非公開項目と import の公開境界を検査する。manifest のない v0.1/v0.2 の既存ファイルは従来の可視性を保つ。
- 依存はルート内に配置済みのローカルパッケージに限定する。実行時にネットワークへ接続しない。lockfile がなければ manifest コマンドで作成し、不一致は `rewind lock` で明示更新する。依存内の `.rw` の相対パスと内容を整列して FNV-128 ハッシュを記録する。これは内容変更の検出用で、署名や暗号学的な完全性検証は v0.4 の提案対象である。
- 単相化は初回呼び出し時に型引数の組ごとに一度生成し、以後キャッシュする。型の入れ子は 64、型引数の文字列は 4096 文字、生成 instance は 4096、生成命令は 100,000 を上限とする。テンプレートと同じ観測に対する生成順序は決定的である。独立した配布用 bytecode ファイルの生成は提供しない。
- trait impl は具体型ごとに記述する。trait の状態、デフォルトメソッド、動的 trait object、関連型、generic impl はこの版の構文に含まない。
- match の範囲は `start..end` の終端を含まない。guard 付き arm や部分的な payload パターンは variant 全体を覆ったことにはしない。必要に応じて `_` を最後に置く。
- guard と cleanup は直接・間接の publish と Checkpoint 操作を拒否する。呼び出し先を静的に確定できない関数値の呼び出しも保守的に拒否する。
- cleanup は失敗しても残る登録を LIFO 順で試行する。通常終了中の cleanup 失敗は最初のエラーを返し、既存エラーの巻き戻し中は元のエラーを優先する。panic の未公開状態は Runtime の破棄によって捨てる。
- Env.get の許可がない場合はエラー。欠落は None、観測済みの値は Journal から再生する。`--secret-env` は取得許可も含み、JSON/text trace に環境値は記載しない。プログラム自身が Out に書いた値は通常の仮想出力として扱う。
- Locale.current は `--locale` の固定値を返し、省略時は `C`。Args.all は起動引数の固定列を返す。Directory.entries は正規化したルート内パスの直下を名前順に返す。
- FileError の `code` と `path` は String、`cause` は Option<String>、`causes` は List<String>。ソース位置は失敗した命令の診断に表示する。
- fmt はコメント・文字列と既存の行分けを保存し、字下げ・行末空白・末尾改行を安定化する。doc は公開シグネチャと直前の /// コメントを Markdown に出力する。複数ファイル check はファイルごとに最初のエラーを集める。

## 確認方法

`cargo test` で v0.1/v0.2 の既存テストと v0.3 の統合テストを実行する。v0.3 は generic と trait、入れ子の型、公開境界、diamond import、lockfile 改変、enum の網羅性、クロージャーの revert/resume、環境観測、ディレクトリ競合、Map キー snapshot、cleanup、開発ツールを検証する。

`cargo clippy --all-targets -- -D warnings` と `cargo fmt --check` で Rust 実装を確認する。`examples/v03.rw` は `item=7` と `13` を publish する。
