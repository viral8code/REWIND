# REWIND v0.9 実装状況

更新日: 2026-10-01。Rust パッケージ版 0.9.0。`language = "0.9"` で v0.8 の機能と以下を選択する。ブランチは `codex/rewind-v0.9`。

## 対話実行と transcript

```sh
rewind repl --root DIR --record session.json
rewind session-replay session.json --root DIR
rewind sign-session session.json --key SEED
rewind verify-session session.json --public-key PUBLIC_KEY
```

REPL は完全な一行入力に加え、`:begin` から `:end` までを一つの入力として扱う。`:cancel` は保留中の入力を捨てる。保留中は変数・Checkpoint・仮想 I/O を変更しない。`:state/:reset/:quit` も利用できる。EOF/quit に未完の複数行入力が残る場合はエラー。応答は `{input,response}` の JSON 行。v0.8 mode の応答形式は維持する。

成功した source prefix だけを採用し、通常 VM で再実行する。失敗した入力の計算・heap・仮想 I/O は直前の成功状態へ戻し、観測は retry 用に保持する。応答は typed diagnostic と原因木を持つ。Checkpoint は VM の論理命令番号を世代として識別し、reset ごとの epoch と区別する。

transcript format 1 は source 入力、command、成功/失敗/保留応答、各入力までの観測 journal、最終状態、epoch、実行手順を保存する。compiler、同じ project root、manifest/lock/source の指紋を要求する。replay は記録にある観測だけを読み、欠落した観測・応答改変・source 変更を拒否する。VM publish は常に仮想化する。通常の run/replay の source fingerprint 検査は変更しない。署名検証は独立した verify-session コマンドで行う。

上限は 256 行、1 行/複数行 cell 64 KiB、source 1 MiB、transcript 32 MiB。候補ごとに VM 100,000 手順、session 合計 1,000,000 手順。失敗した候補と再実行した prefix も合計へ加算し、reset で予算を戻せない。型検査・const 評価の予算はそれぞれ既存規則。履歴 memory/storage は各 4 MiB。

transcript は source と通常の観測を保存する。Secret/reveal と秘密観測を使う transcript は初版で拒否し、秘密の再供給 protocol は次版へ送る。record を指定しない REPL は既存の秘密表示の伏せ方を使う。live task、async/tasks、cleanup、runtime 予算変更、途中の宣言変更、定義置換、VM 継続の永続保存は対象外。プログラムの In は EOF、環境変数の許可 UI は初版に含めない。

## 公開 API の契約

```sh
rewind api-snapshot --root DIR --output before.json
rewind api-diff before.json after.json --deny-breaking
rewind api-convert old-format-1.json --root DIR --output format-2.json
```

v0.9 snapshot は format 2。公開関数・型・trait・alias・const に加え、公開型/trait の impl、関連型の具体化、generic 制約、method の効果・所有権を保存する。読み込んだ依存 module の public interface と公開 impl も保存する。依存の追跡は保守的で、public API の型が直接参照しない public export の変更も dependency 契約変更として表示する。通常の関数本体だけの変更は除外し、trait default の本体は引き続き契約に含める。

const は初期化式と評価値の SHA-256 を分ける。heap ID に依存しない値を作り、関数値には参照する関数の本体も保守的に含める。型と評価値が等しく式だけ変わった場合は initializerChanged/nonbreaking。評価値が変わった場合は breaking。const の暗号化や任意の関数の数学的同等性証明は行わない。

format 1 と 2 の直接比較は拒否する。api-convert は現在の検査済み v0.9 ソースの旧形式相当の契約と照合し、一致した場合だけ不足契約を補う。古い snapshot だけから未保存の impl や const 値を推測しない。入力/出力は各 8 MiB。

## production-only 配布

```sh
rewind install --production --root DIR --output NEW_DIR
rewind run --root NEW_DIR
rewind build --root NEW_DIR --output program.json
```

通常 source と実行依存の package source/metadata/signature を新規 directory にコピーする。開発用 package、署名用秘密鍵、任意の asset、cache はコピーしない。source/package の合計 32 MiB。既存 directory は上書きしない。任意の Host fixture や asset は別途配布する。

manifest の `dependency_mode = "production"` が実行依存だけを選ぶ。元の lock に固定した runtime 部分と、実際に配置された package の署名・hash・版・効果・推移制約・trust/失効を照合する。実行の fingerprint には再検証した runtime lock 部分だけを使い、未検証の開発 graph を executable artifact へ取り込まない。通常依存から到達する開発指定 package は runtime として残す。

開発依存は配置不要。test/doctest/update は完全な開発 graph を必要とするため production mode では拒否する。開発用 package が欠けたことを runtime の署名不正と混同しない。開発専用 module の path import も拒否する。ネットワーク fetch は導入しない。production mode は lock の開発部分の authenticity を保証する mode ではない。

## generic record と property

```rewind
record Box<T:Share>{value:T}
fn same<T:Share>(box:Box<T>)->Box<T> effects {}{return box;}
let box=Box((3,true));
assert_eq(same(box).value._0,3);
```

record の全型パラメータに Share を要求し、型を代入した全フィールドの深い不変性を検査する。constructor・型注釈・未使用関数の signature・verified artifact で検査する。可変 List/Map/struct は Frozen にする。generic enum の bound 宣言や phantom parameter の明示 constructor 推論は別の拡張候補。

```rewind
type Generator<T>=fn(Int)->T effects {} captures {Send,Share};
record Source<T:Share>{generate:Generator<T>}
```

透明 alias と generic record で生成器を再利用できる。`propertyCandidates(seed,cases,generator,shrinker,predicate)` は `property` と同じ PropertyCase<T> を返す。shrinker は `fn(T)->Frozen<List<T>> effects {} captures {Send,Share}`。全 callback と T の Share/purity 契約を保つ。

候補は列の順に試し、最初の失敗候補へ進む。評価済みの値を heap ID に依存しない digest で除去する。1 回の shrinker は最大 64 候補、predicate の縮小評価は合計 64 回。入力生成は最大 100,000 case。任意の非単調 predicate の大域最小は保証しない。audit に seed、case、縮小入力、shrinks、evaluations、探索方式 ordered-candidates-v1 を保存する。既存 property/propertyInt も使える。

## 編集と表示

未完ソースの completion/hover/signature help は最後に検査できた宣言を使う。completion の data.provisional、signature help の data.provisional、hover の注記で区別する。初めて入力した未検査の declaration の推測は行わない。壊れた body・閉じていない string/comment を含む編集に対応し、diagnostic は現在の source のまま。definition/references/rename は検査済み workspace を要求する。元 source へ書き込まない。

```sh
rewind sign-inspection inspection.json --key SEED
rewind verify-inspection inspection.json --public-key PUBLIC_KEY
rewind timeline inspection.json --public-key PUBLIC_KEY --count 100
```

inspection と session は独立した Ed25519 署名 domain を持つ。trace の署名を流用できない。timeline/debug-session は inspection を表示する場合に inspection の署名を検査する。export 時の source_signature_verified フラグと、bundle 自体の署名検証は区別する。

timeline JSON schema は rewind-timeline/v1。task 状態、typed cause、仮想ファイル差分、audit を持つ。LSP の `rewind/timeline` request は `{uri,from,count,task,publicKey}` を受け、同じ JSON を返す。stdio に JSON frame 以外を出さない。editor が原因木・task・file 差分を表示するための interface と例を提供する。

raw indexed trace の読み取り期間は 0.8.0/0.9.0。raw 0.7.0 は拒否し、長期保存した inspection format 1 は 0.7/0.8/0.9 由来を表示できる。artifact/replay/secure lock は exact 0.9.0、cache は実装ハッシュ一致。trace/index の予算は既存の 128 MiB、1 request 1,000 event。
