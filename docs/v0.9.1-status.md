## JSON と設定

`Json` は immutable enum: Null / Bool(Bool) / Int(Int) / Float(Float) / Text(String) / Array(Frozen<List<Json>>) / Object(Frozen<Map<String,Json>>)。recursive な Json は Share。JsonError は code/line/column/offset を持つ immutable record。parse 失敗に入力値を含めない。line/column は 1 始まり、offset は UTF-8 byte 数。syntax の位置は不正 token の開始。

native primitive の公開 facade は [libraries/std/json.rw](../libraries/std/json.rw)。parse(String)、parseBytes(Bytes)、stringify(Json) は Result。get/keys/kind/integer/floating/text/boolean/array は明示変換。UTF-8、duplicate key、数値範囲、syntax、byte/depth/item 予算を検査する。1 MiB、深さ 64、65,536 node。整数は signed 64-bit、Float は有限 IEEE-754 binary64、decimal/exponent は Float とする。Float の丸め/underflow は IEEE-754 に従う。object key は UTF-8 の辞書順、入力順は保持しない。stringify は compact/canonical order で、浮動小数の数学的 canonicalization/JSON署名仕様ではない。

Secret は stringify の引数型へ渡せない。明示的に reveal した String は Json::Text へ変換できるため、アプリは公開可否を決める必要がある。任意 record の自動 reflection/codec は未実装。schema で Json を検証し、明示変換して domain record を構築する。

[config](../libraries/std/config.rw) は必要項目、型、fallback、未知項目、重複 schema を検証する。優先順位は arguments > environment > file > fallback。環境/引数は caller が Json object に変換し、Args/Env/File の観測と許可を隠さない。上限 128 field。ConfigError の field は宣言した schema 名だけにし、未知入力名/値は表示しない。[args](../libraries/std/args.rw) は明示名の `--name VALUE` に対応する。bool flag、短い option、help、schema の自動生成は次版へ送る。

## application entry と失敗

root module の同期 `fn main()->Int` を top-level statement の後に一度呼ぶ。引数は Args API を使う。既存スクリプト入口は維持し、test では main の自動呼出しを省く。main は publish を明示する。return 0 は成功、1..63 は業務状態。appStatus(Int,String) は script からも同じ状態を指定でき、秘密登録済みの message は伏せる。0 は継続し、非ゼロは終了処理・cleanup を伴う失敗となる。

CLI は `--diagnostic-format text|json` を受ける。JSON は exit_status/message/diagnostic/ retryable/retry_hint。`--` 以後はアプリの引数として保持する。

| code | 意味 |
|---|---|
| 0 | 正常終了 |
| 1..63 | アプリが返した業務状態 |
| 64 | CLI/manifest/配布/一般的な外側の失敗 |
| 65 | 型/効果/通常の Diagnostic failure |
| 70 | panic、cleanup を含む複合失敗 |
| 71 | 実行/履歴/task 等の予算超過 |
| 72 | publish 前の external state conflict |
| 73 | PublishPartiallyApplied |
| 74 | task cancellation |

原因木を保持し、部分 publish は自動 retry 不可。conflict は再読込とアプリの判断を要求する hint を返す。以前の publish や外部操作まで取り消せると仮定しないため、自動 retry フラグは既定で false。

## asset と release

```toml
[assets]
config = "assets/config.json"
```

allowlist の通常ファイルだけを lock の assets に SHA-256/bytes として固定する。256 file、合計 32 MiB。絶対 path、親 path、symlink、重複 path、source/管理ファイル、.git/.rewind/target、一般的な鍵拡張子を拒否する。update は明示した内容を再固定し、通常 run/build/production install は欠落・改変を拒否する。mutable state/秘密情報を asset に指定しない。

install --production は source/package 32 MiB と asset 32 MiB を新規 directory へ配置し、rewind.release.json を生成する。compiler/language/target/entry/effects/default step/asset budget、lock digest、source digest、asset inventory を記載する。任意の credential/cache/record/state は allowlist にないのでコピーしない。入力と target が同じなら manifest とファイル内容は再現できる。archive / SDK / cross-target build はまだない。

`sign-release FILE --key SEED` / `verify-release FILE --public-key KEY` は独立した Ed25519 domain を使う。verify は署名の後に root の source/lock/assets/entry/effects を照合する。run 自体は release signature を自動検査しないので、配布利用者は verify-release を実行してから起動する。artifact には asset inventory を含め、署名した artifact も source-free run 前に asset digest を検査する。

## ライブラリと保存例

[ライブラリ一覧](../libraries/README.md) に JSON/config/args/collections/math/option を提供する。generic parameter の None 推論と、module alias 経由の generic borrow argument の検査を補修した。Map value の serialization を key/value pair 列にし、Map を含む AST の trace/artifact/debug の保存を可能にした。

[examples/v091](../examples/v091/README.md) は JSON→State record→単一 state.json の保存、既存 state の読取り、Args/Env の上書き、業務失敗、record/replay、asset/release/artifact の例。ファイルの単一置換と既存の publish 前の競合検査を利用する。確認から置換までの process lock、power-loss durability、複数ファイル atomicity は保証しない。実運用は一 writer を前提とする。
