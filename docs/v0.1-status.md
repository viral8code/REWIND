# v0.1 implementation status

The source of truth for intended behavior is [REWIND_v0.1.md](REWIND_v0.1.md). This checklist records what the Rust code currently verifies and what is still required before calling v0.1 complete.

## Implemented

- Named checkpoints, revert, branch, drop, parent links, and copy-on-write compute roots.
- Globals, heap objects, stack, call frames, locals, program counter, random generator state, and deterministic object/handle IDs.
- Virtual stdout/stderr with immutable journal nodes, spill to temporary storage, prefix-safe publish, and input/time observation replay.
- Virtual file create/write/append/truncate/delete/copy/move and directory create/delete/move; 4 KiB shared file pages and file-handle cursor restoration.
- Lazy block reads through file handles, strict whole-file snapshots, read-your-writes, and external-change detection for ordinary file writes and uncached reads.
- Publish validation, staged per-file replacement, deletion, stdout/stderr ordering, and explicit force mode.
- Configurable history memory/storage budgets for output journals, overlay pages, and estimated compute payloads.

## Remaining before v0.1 completion

1. **File-delta spill:** Large virtual file pages currently remain in RAM. Spill them to temporary storage while preserving page sharing and rollback. Budget host observation caches and file-handle snapshots as well.
2. **Host observation validation:** Use a stronger version identity for lazy file blocks and close the race between validation and publication as far as the platform allows. Test same-size edits and concurrent changes.
3. **Publish recovery:** Persist enough progress to report which resources were applied if a multi-resource publication fails. Keep staged cleanup and output retry behavior unambiguous.
4. **Language execution model:** Define and implement normal control flow and function calls so stack and call frames are exercised by scripts, rather than only the Rust API. Clarify where execution resumes after `revert`.
5. **Unsafe external operations:** Either define a narrow unsafe provider and taint behavior or document a strict prohibition in the v0.1 language surface.
6. **Specification ambiguities:** Section 38's input example conflicts with the cursor behavior in sections 11–12. The implementation follows sections 11–12; this needs an explicit erratum.

The v0.2 language design document is intentionally deferred until these items are resolved. It must be stored outside this Git repository, per the user's request.
