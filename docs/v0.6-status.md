# REWIND v0.6 実装状況

更新日: 2026-09-30。状態: **実装済み（対応範囲・上限は以下に記載）**。Rust パッケージ版は 0.6.0。

[v0.6 設計案](REWIND_v0.6.md) の残項目を実装した。採用した構文と保守的な制限を本書に記載する。下記の追加機能は `language = "0.6"` の manifest で選択する。v0.1〜v0.5 の規則は既存テストで検証する。

## 実装済みの範囲

### 関数効果

```rewind
fn apply<E:Effect>(f:fn(Int)->Int effects E,n:Int)->Int effects E {
    return f(n);
}
assert_eq(apply(|n:Int|->Int{return n+1;},4),5);
```

- 効果パラメータは `<E:Effect>`。通常の型パラメータと区別する。
- 関数型は `fn(Int)->Int effects {output}`。効果を省略した関数型は全標準効果を要求する。
- private 関数の効果は固定点で推論する。128 回の更新と式の深さ 128 を上限とする。public 関数は明示した効果を必要とする。
- 関数値、別名、match、返却された関数、コンテナの型に効果を保存する。再代入は変数の効果上限を超えられない。
- trait のメソッドに `effects {...}` を指定できる。省略時の上限は空集合。impl が上限を超えると拒否する。
- generic の定義では trait 契約の上限を検査し、具体的な呼び出しでは引数型で特殊化した本体の効果を使用する。循環する特殊化では宣言上限へ戻る。library/async の publish は効果変数でも許可しない。
- `effects {E,F,output}` の包含制約に対応する。個別の変数の制約を先に集め、残った効果は名前順の最初の変数へ割り当てる。効果不足の Diagnostic は呼び出し位置と操作位置を原因木に持つ。

### 同期の借用と部分移動

```rewind
fn count(xs:&List<Int>)->Int effects {} {return xs.len();}
fn append(xs:&mut List<Int>,n:Int)->Unit effects {} {xs.add(n);}
let xs=List<Int>();
append(&mut xs,7);
assert_eq(count(&xs),1);
```

- 呼び出し時に `&` / `&mut` を要求し、競合する引数を拒否する。借用済みの変数も同期借用引数に渡せる。
- 共有借用を通じた更新、借用を含む戻り値、非同期借用引数、借用から取り出した可変所有者の返却を拒否する。
- `move value.field` はそのフィールドを使用不可にする。他のフィールドを読み取り・更新できる。
- `&value.field` / `&mut value.field` は同じ領域の移動・更新と競合する。ブロック終了で解放される。Checkpoint は所有権検査の状態を復元する。
- trait/impl の receiver にも `&Self` / `&mut Self` を指定できる。共有借用からの呼び出しには共有 receiver 契約を要求し、引数を評価する間の receiver 借用競合も検査する。

### 明示的なクロージャー捕捉

```rewind
var n=7;
let snapshot=capture value ||->Int{return n;};
n=9;
assert_eq(snapshot(),7);
let xs=List<Int>();
{
    let read=capture borrow ||->Int{return xs.len();};
    assert_eq(read(),0);
}
xs.add(1);
let owned=capture move ||->Int{return xs.len();};
assert_eq(owned(),1);
```

- `capture value` は捕捉したセル・コレクション・関数の値を深くコピーする。FileHandle や借用を含むコピーは拒否する。
- globals に依存する名前付き関数を直接 value 捕捉する形は拒否する。必要なデータを明示的に捕捉する。名前付き関数・メソッドを経由する globals も捕捉契約に含める。receiver 型が未確定の場合は候補メソッドの依存を保守的に含める。
- `capture move` は捕捉した所有者を使用不可にし、クロージャーへ渡す。部分移動済みの所有者や借用中の所有者は捕捉できない。
- `capture borrow` は共有借用。捕捉元の更新・移動と、捕捉した値を通じた更新を拒否する。immutable な `let` に束縛し、その lexical scope 内で呼び出す。
- 借用捕捉は返却・集約値への保存・所有引数への受け渡し・タスク転送を禁止する。同期の `&fn(...)->... effects {...}` 引数へ、束縛済みの借用クロージャーまたは一時的な `capture borrow` を渡せる。捕捉元の借用は全引数の評価が終わるまで維持する。可変借用捕捉は採用していない。
- Checkpoint より後に作られた参照・所有者は revert 後に使用できない。保存前の借用状態・部分移動状態は復元する。
- 捕捉した値とセルは Checkpoint で復元する。公開関数型に `captures {Send}` / `captures {Send,Share}` / `captures {}` を指定できる。省略時は Send を要求する。Share は Send も要求する。可変セル・可変コレクションは Share にならず、借用捕捉は Send/Share のどちらにもならない。型注釈・引数・戻り値・コンテナ・成果物でこの契約を保持する。

### 診断とタスク

- v0.6 Diagnostic は `code`, `message`, `source`, `line`, `column`, `taskId:Option<Int>`, `causes:List<Diagnostic>`, `waitGraph` を持つ。行・列は 1 始まり。
- 原因木は失敗発生時と cleanup 時に構築する。cleanup 用の表示文字列を分割して復元しない。
- TaskGroup.join は登録順に失敗を集約する。第一原因の cleanup 原因を保持し、残りのタスク失敗を追加する。
- WaitGraph.edges は `List<WaitEdge>`。辺は `task:Int`, `target:WaitTarget` を持ち、target は Task/Channel/Group の ID。
- BudgetKind は ExecutionSteps, TaskSteps, SchedulerStorage, SchedulerObjects, TransferDepth, TypeExpansion, Monomorphization, HistoryMemory, HistoryStorage, IteratorItems, EffectInference, DependencyResolution を区別する。history の memory/storage は実際に超過した予算から判定する。
- `task.requestCancel()->Unit` は取消し要求。`task.cancelAndJoin()->Task<T>` は取消しを行って結果を await できる Task を返す。既存 cancel も利用可能。
- 記録された主タスクの失敗には型付き diagnostic を保存し、replay で結果との一致を確認する。
- `task.timeout(steps)->Task<T>` は開始時から scheduler の論理命令数を数える。待機タスクしかない場合は次の期限へ進む。期限切れでは対象を取り消して cleanup 終了を待ち、`TaskError::TimedOut` を返す。cleanup が失敗すると LogicalTimeout の Diagnostic に原因を残す。
- `left.select(right)->Task<(Int,Result<T,TaskError>)>` は同じ結果型の二つの Task を開始し、完了した側を 0/1 と結果で返す。同時完了は左を選ぶ。選ばれなかった Task は呼び出し側で join/cancelAndJoin する。期限・選択・論理時計も Checkpoint で復元する。

### 標準 API

| API | 戻り値・規則 |
|---|---|
| String.byteLen / charLen / utf16Len | Int。バイト・Unicode scalar・UTF-16 code unit の数 |
| String.encodeUtf8 | Bytes |
| Bytes.decodeUtf8 | Result<String,String>。不正 UTF-8 は Err |
| String.contains / startsWith / endsWith | Bool |
| String.find | Option<Int>。バイト位置 |
| String.split | List<String> |
| String.slice / Bytes.slice | バイト範囲 `[start,end)` の Result。UTF-8 境界違反を拒否 |
| String.parseInt / parseFloat | Result。i64 の overflow、非有限 float を拒否 |
| Int.format / Float.format | String |
| Int.toFloatChecked / Float.toIntChecked | Result。不正確な変換と overflow を拒否 |
| Float.isFinite / isNaN | Bool |
| Result.map / mapErr / andThen / flatten | 型とエラー型を維持。callback は同期関数 |
| Iterator.map / filter / take / fold / collect / enumerate / zip | カーソルを消費。独自 Iterator.next にも対応 |

tuple は `(value0,value1,...)`、型は `(Type0,Type1,...)`。単一要素には末尾のカンマを使う。`()` は Unit。フィールドは `_0`, `_1`, ... で読み取り、フィールド自体の代入はできない。可変所有者を tuple に入れる場合は `move` を要求する。tuple の Send/Share は各要素から判定する。`let (a,(b,c))=...;` / `var (a,b)=...;` と match の tuple pattern に対応する。let/var pattern は束縛・tuple・`_` のみ。重複した束縛名と要素数の不一致は拒否する。所有者を含む既存の値は `move` して分解する。match で移動せずに取り出した可変所有者は共有借用として扱う。

`type Pair<T>=(T,String);` は透明な型 alias。型注釈、シグネチャ、フィールド、generic 型、impl 対象・関連型で展開する。非公開 alias と名前衝突を検査し、循環・深さ 64 以上は TypeExpansion の予算エラーになる。

trait 内にメソッド本体を置くと default method になる。未使用の default も trait 契約で検査する。impl に明示 override があればそちらを使い、なければ Self・関連型・impl generic を置換して本体を生成する。alias 展開で同じ impl になった場合も拒否する。

`propertyInt(seed,cases,min,max,predicate)->Result<Unit,PropertyFailure>` は純粋な `fn(Int)->Bool effects {}` を検査する。整数入力を SplitMix64 で生成し、失敗時は範囲内で 0 に最も近い値へ縮小する。PropertyFailure は seed / case / input / shrinks を持つ。case は 0 始まり。最大 100,000 case、縮小探索は最大 64 回。境界への二分探索なので任意の非単調 predicate の大域最小は保証しない。生成状態は Runtime.random を消費せず、同じ seed・範囲・predicate から同じ結果を返す。

`enumerate()` は `(Int,Item)`、`zip(other)` は `(LeftItem,RightItem)` を要素に持つ Iterator を返す。zip は短い側が終了した時点で停止し、両方のカーソルを進める。右側が先に終了した場合は左側を 1 要素余分に消費することがある。長さを確認するための走査は行わない。

Iterator adapter は現時点では**即時評価**。map/filter/take は結果を持つ新しい Iterator を返す。1 操作 100,000 要素を上限とし、走査は実行予算も消費する。fold は accumulator、collect は List を返す。callback の tasks / publish は許可しない。保存済みカーソルは Checkpoint で復元される。

Secret の算術・比較・フィールド・標準メソッド結果は Secret として保持する。コンテナの表示も再帰的に伏せる。Secret を受ける callback とユーザーメソッドは明示 reveal を必要とする。reveal 後の値も診断・デバッグ表示では伏せるが、通常の出力や仮想ファイルへの書き込みはプログラムが明示的に行える。

`In.readSecretLine()->Option<Secret<String>>` と `Env.getSecret(name)->Option<Secret<String>>` は外部秘密観測。入力の記録には `{secret:true}`、環境には秘密マーカーを保存し、plaintext を保存しない。`run/replay --secret-input FILE` は秘密入力だけを行順に供給する（最大 1 MiB）。環境は `--allow-env NAME` で許可し、replay では `--secret-env NAME` で外部から再供給する。欠けた再供給を拒否する。

trace の audit は secretInput / secretEnvironment / reveal の操作位置と task/event を記録し、値を持たない。デバッグ index・最終状態・原因・ファイル差分も記録終了時に改めて伏せる。ソース・cache・artifact の秘密リテラルは暗号化しない。通常の trace 暗号化は対象外。

### ツール

- v0.6 の LSP は差分同期を宣言し、複数の変更を順に適用する。UTF-16 の surrogate pair の中間、範囲外、古い document version を拒否する。
- 未保存の編集は検査用の overlay に保持する。元のソースには書き込まない。
- v0.6 成果物も署名・標準型の配置・型検査・効果再推論・再コンパイルによる検証を行い、ソースなしで実行できる。

## 増分ビルドと依存更新

- `.rewind/cache` に module 解析、関数検査、関数命令列を保存する。キーは compiler 実装のハッシュ・内容・型/効果/捕捉契約・依存 interface を含む。所有権検査・効果推論・署名検証は毎回実施する。interface の変化は保守的に関数検査を無効化する。
- cache は HMAC-SHA256 で認証する。Unix の秘密鍵は project 外の temporary directory（実行ユーザー所有の 0700、鍵 0600）に置く。非 Unix・鍵消失・書込不能・破損・不正認証では通常の再構築へ戻る。symlink を cache として使わない。最大 512 entry、entry payload は 8 MiB。`REWIND_NO_CACHE=1` で全再構築する。同じ OS ユーザー自身が鍵を改ざんする攻撃は境界外。
- mirror は `[dependencies]` / `[registry]` の値を `file:vendor/pkg1 | file:vendor/pkg2` のように指定する。署名・信頼鍵・失効・名前・版・推移制約を検査し、版の降順・path の順で backtracking する。通常は既存 lock の候補を優先し、update は最新の有効な graph を選ぶ。最大 4096 探索、深さ 128。
- `rewind update --root DIR --preview --output plan.json` は lock を変更せず、採用理由・旧/新 metadata・trust/effects の変化・提案 lock を表示する。`rewind update --root DIR --apply plan.json` は現在の manifest・lock・選択 graph・署名・trust で提案を再計算し、一致する場合だけ lock を atomic rename する。古い案は StaleUpdateProposal。ネットワーク fetch は行わない。

### 配布形式の互換表

`rewind compatibility FILE` は形式と compiler から JSON で可否を説明する。この判定に成功しても、使用時の通常の署名・型・効果・内容検証は省略しない。

| 種類 | 読める format | compiler | 変換 |
|---|---|---|---|
| v0.5/v0.6 verified artifact | 2 | exact 0.6.0 | なし。他版は再 build |
| trace | 1 | exact 0.6.0、replay は fingerprint も一致 | なし。他版は再 record |
| secure lock | 2 | exact 0.6.0、manifest と一致 | update で再生成 |
| cache | compiler 実装ハッシュに一致する内部形式 | exact 実装 | 不一致・破損は再構築 |

旧 language mode の bytecode template は verified artifact として扱わない。同じ package version でもソース/型/標準 API が変わった artifact は通常検証で拒否される。

## LSP と記録デバッガ

- LSP は lexical binding の定義・参照・rename、名前付き関数・メソッド・型の参照、signature help、原因の relatedInformation、move と効果宣言の quick fix に対応する。rename は同名の別スコープの binding を変更しない。返却する編集を overlay に適用して workspace の型・効果・所有権を再検査し、不完全な編集を拒否する。trait のメソッドと impl は同じ契約として索引化する。
- 不完全な呼び出しの signature help は保存済み宣言を fallback として使う。他の意味解析要求は型検査可能な文書が必要。rename は名前衝突を保守的に拒否し、異なる selective import alias を一括で変更する要求も拒否する。quick fix は候補の編集を返し、適用は client が行う。
- v0.6 の `run --record FILE` は命令位置と表示状態の可逆差分を保存する。256 命令ごとの anchor により探索時の prefix 再実行を避ける。index は 16 MiB、trace 全体は 128 MiB。記録した検査済み artifact の fingerprint と index を結ぶ。
- `debug-session FILE --root DIR` では step / back（reverse-step）/ next-line / previous-line / continue / reverse-continue / `break SOURCE:LINE` / `clear SOURCE:LINE` / `task ID` / `checkpoint NAME` / state / tasks / files / `diff EVENT` を使用できる。task 選択は step・line・breakpoint の探索にも適用され、待機タスクの保存 frame も表示する。
- index がある trace はソース・manifest・秘密の再供給なしで表示状態を再構成する。VM を実行せず、Host の観測・publish・trace 変更を行わない。`--public-key KEY` で trace の署名を検証できる。index のない旧記録は既存の source replay 表示へ戻る。
- files/diff はそのイベントで保持している仮想ファイル差分を表示する。publish 後に消えた差分は publish 前へ戻って確認する。内容表示は既知の 64 KiB 以下のデータに限定し、未観測の Host ファイルは読まない。

borrowed return、可変借用捕捉、動的 trait object、型ごとの合成 property generator、異なる compiler 版への形式変換、暗号化 trace は採用していない。フィールド借用と部分移動の解析は保守的に競合を拒否する。

## 検証

- 既存 104 件と v0.6 の 24 件、合計 128 件の回帰テスト。

- v0.6 テストは pure callback、効果不足、trait 上限、借用競合・返却・転送、部分移動、文字列・数値変換、Iterator の Checkpoint 復元、cleanup 原因木、TaskGroup 集約、取消し、source-free artifact、UTF-16 差分同期を確認する。
