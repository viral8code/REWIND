# REWIND v0.8 実装状況

更新日: 2026-09-30。Rust パッケージ版 0.8.0。`language = "0.8"` で v0.7 の機能と本書の採用機能を使う。

## 用途別依存

```toml
[dev_dependencies]
checks = "file:vendor/checks"
[dependency_versions]
checks = "^1.0"
[dependency_signers]
checks = "author"
[trust]
author = "ED25519_PUBLIC_KEY_HEX"
```

通常依存と開発依存を合成し、推移制約・mirror・署名・trust・失効を検査して単一 lock に保存する。通常の run/check/build/doc/api-snapshot/repl は通常依存から到達する package だけを import できる。開発依存の package path をローカル import で迂回しても拒否する。test/doctest は合成 graph を使う。記録された test の replay も同じ graph と文書 fingerprint を検証する。

通常依存の推移依存として必要な package は、root で開発用に指定していても通常 graph に残る。通常/開発で同じ直接依存名を重複指定できない。署名と lock の検査対象は mode で変えないため、開発用 package もローカルに配置する必要がある。production-only install は対象外。ネットワーク fetch は行わない。

## 失敗入力を取り消す REPL

```sh
rewind repl --root DIR
```

完全な一行入力を逐次検査する。複数の statement と function body は一行にまとめる。`:state` で現在の変数・heap・Checkpoint・仮想ファイル差分・出力を表示し、`:reset` で session 全体を消去し、`:quit`/EOF で終了する。各入力へ JSON で ok/error/diagnostic/state を返す。既存の entry ソースは自動実行しない。

成功した source prefix だけを session に採用し、毎入力を通常 VM で最初から再実行する。既に観測したファイル・時計などは session 内の journal から再利用し、新しい観測だけを追加する。失敗入力の観測は retry 用に保持するが、変数・heap・Checkpoint・仮想 I/O は直前の成功状態へ戻す。型エラーの入力も採用しない。Checkpoint の commit/revert/resume は通常 VM の規則で入力間に利用できる。

publish は常に仮想化する。Host へのファイル変更と出力は発生せず、JSON 応答の stdout/stderr で仮想出力を確認できる。プログラムの In は EOF（標準入力は対話コマンド用）。外部環境変数の許可 UI と秘密の外部再供給は初版に含めない。Secret の値・reveal 済みの診断と状態は伏せる。

上限は 256 行、1 行 64 KiB、accepted source 1 MiB、各候補の VM 実行 100,000 手順、履歴 memory/storage 各 4 MiB。関数・型・trait・impl・alias の宣言は実行入力の前に置く。途中で過去の dispatch や効果が変わる宣言を拒否する。async/tasks、defer/using、runtime の予算変更を拒否する。live task の継続、定義の置換、複数行編集、session 自体の永続 trace は対象外。再実行で prefix の計算量が増えるため長い session は reset を使う。

## 読み取り専用の互換と export

| 種類 | v0.8 の扱い |
|---|---|
| indexed trace format 1、compiler 0.7.0/0.8.0 | ソースなしの timeline/debug-session 表示 |
| index のない trace | exact 0.8.0 の既存表示のみ |
| replay / verified artifact format 2 | exact 0.8.0、通常の署名・型・効果・内容検証 |
| secure lock format 2 | exact 0.8.0、update で再生成 |
| API snapshot format 1 | compiler に依存しない api-diff |
| inspection bundle format 1 | 表示専用。実行/replay に使えない |
| cache | 実装ハッシュ一致。旧 entry は再構築 |

```sh
rewind compatibility session.json
rewind trace-export session.json --output inspection.json --public-key PUBLIC_KEY
rewind timeline inspection.json --count 100
rewind debug-session inspection.json
```

compatibility は readable/viewable/executable/replayable/conversion_available を区別する。可否の表示は通常検証を省略しない。v0.7 記録の表示互換は 1 世代の期間とし、以後の期間は次版で明示する。

export は indexed trace 128 MiB まで。patch を検査し、最終 runtime/scheduler 状態を照合する。新規ファイルへ inspection JSON を保存する。元 compiler、入力 bytes の SHA-256、署名検証の有無、event/index/原因木/audit を保持し、ソース・観測 journal・実行 fingerprint・署名はコピーしない。秘密の伏せ方を維持する。元記録・既存ファイル・symlink・hardlink を上書きしない。bundle は timeline/debug-session で読めるが VM を実行できない。署名の検証済みフラグは export 時の説明であり、bundle 自体の署名や authenticity を保証しない。

## 検証と例

既存 135 件と v0.8 の 10 件、合計 145 件の回帰テスト。失敗 REPL 入力の heap/file/Checkpoint 復元、型エラー/reset、観測の再利用と予算、開発依存の mode 分離・path 迂回禁止・署名・lock・test replay、通常推移 graph、実際に v0.7.0 で生成した fixture の source-free 表示と replay 拒否、export の秘密伏せ・署名・破損 index・上書き禁止、v0.7 機能と verified artifact を確認する。const の間接関数呼び出しにも境界検査を適用した。

`examples/v08` の通常実行は `7` を出力する。`rewind test examples/v08/tests.rw --root examples/v08` と `rewind doctest examples/v08/manual.md --root examples/v08` は署名済み開発依存を使用する。次版は [v0.9 案](REWIND_v0.9.md)。
