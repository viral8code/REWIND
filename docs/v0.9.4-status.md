# REWIND v0.9.4 実装状況

更新日: 2026-10-01。compiler/package 0.9.4、language 0.9.4。作業branchは`codex/develop`。[計画](REWIND_v0.9.4.md)のCLI・増分publish・primitive Map・bounded streamingと明示generic callを初回実装した。計画全体の完了ではなく、残る課題は[v0.9.5草案](REWIND_v0.9.5.md)に集約する。

## 手軽なCLI

```sh
rewind run main.rw
rewind compile main.rw
rewind run main.rwc
rewindc main.rw
rewind main.rwc
```

manifestがなければsource directoryをrootとするlanguage0.9.4設定を内部で作る。manifest/lock/vendorの生成やupdate/sdk-installを要求しない。compiler内蔵stdを`.rewind/std-0.9.4`へ展開し、内容照合・修復とsymlink拒否を行う。外部packageは自動取得しない。compileの既定出力はsourceと同じ場所の.rwc、既存の検証済みportable artifact形式である。runはsource変更を再読込し、既存parse/module cacheを利用する。

既定effectsはinput/output/args/locale/random/tasks。fileRead/fileWrite/env/clockは`--allow-effects`で明示する。artifactの要求effectも実行時に検査する。近傍manifestがあればその設定とlock/署名検査を優先し、明示`--root`も維持する。既存projectのlanguageは自動変更しない。

## 増分publish

language0.9.4のpublishはpending操作だけを確定する。操作IDと確定ledgerはCheckpointに戻さず、revert/branch復元で確定済み操作を再送しない。異なる操作の同じ文字列は別々に出力する。

```rewind
var score = 10;
commit test1;
score = 99;
Out.println(score);
commit test2;
publish;
revert test1;
Out.println(score);
publish;
```

出力は99、10の順。commitは計算状態とpending I/Oを保存し、publishは外部への確定である。最初のpublishがなければ99はrevertで破棄され、10のみ出る。fileの確定済みdeltaも再適用しない。古い未公開file deltaと現Hostの競合は拒否し、stdout/stderrの途中失敗はrevert後も再publishを拒否する。複数file/streamの一括atomic性は保証しない。旧language modeのpublish規則を維持する。

## storage・型・streaming

primitive key Mapはpersistent AVL。root clone O(1)、get/set/removeのnode path O(log n)、entry payloadはArcで共有しlogical byte totalを集計する。返すpayloadのclone費用は別で、user Ord OrderedMapは線形のまま。profileはMap node生成数、paged node/slot参照copy数を追加する。物理allocation byteやnative work全体の予算ではない。

`module.create<T>(...)`形式の明示generic callを解決する。複数boundや期待戻り型factory推論はまだ追加していない。

`In.readChunk(1..65536)->Option<Bytes>`は短いreadとEOFを記録し、Checkpoint復元では記録済みbyteを再生する。`Out.writeBytes(Bytes)`はpublishまでpending。`std.stream`はpureなtoken feed/next/nextInt、incremental UTF-8、bounded writer/drainを提供する。容量・形式失敗のpreflight、Int64最小値、UTF-8分割境界を検証する。詳細な上限と位置の意味は[libraries](../libraries/README.md)。input観測は履歴予算に課金し、無制限の入力を保証しない。
