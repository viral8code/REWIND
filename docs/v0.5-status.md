# REWIND v0.5 実装と運用

作成日: 2026-09-30。Rust パッケージ版: 0.5.0。

設計案 [REWIND_v0.5.md](REWIND_v0.5.md) の構文を以下の規則で具体化した。新規則は `rewind.toml` の `language = "0.5"` で選択する。旧版の実行規則は維持する。

## 1. 所有権、snapshot、転送

```rewind
async fn count(xs: Frozen<List<Int>>) -> Int effects {} {
    return xs.len();
}
let xs = List<Int>();
xs.add(7);
let frozen = freeze(xs);
let independent = thaw(frozen);
independent.add(8);
let task = spawn count(frozen);
assert_eq(await task, Ok(1));
```

- `freeze(T) -> Frozen<T>` は独立した深い不変 snapshot。`thaw(Frozen<T>) -> T` は独立した可変コピー。FileHandle、関数を含む値、循環する参照は凍結できない。
- Frozen は読み取り API とフィールド参照を持つ。集約値の読み取り結果も Frozen。更新には thaw が必要。iter は新しいカーソルを返す。
- `move owner` は名前付き所有者を移し、元の名前を使用不可にする。可変所有者の単純な別名作成と通常関数への受け渡しには move または freeze が必要。
- `let view = &owner;` と `let view = &mut owner;` は字句スコープの借用。共有借用中の更新、重複した可変借用、可変借用を保持した await、借用を引数や戻り値として外へ出す操作を拒否する。借用引数を持つ関数シグネチャはこの版では導入しない。
- 所有権の状態は checkpoint に保存し、revert/resume で戻す。分岐の一方で移動した名前は分岐後も使用不可。反復ループ内で外側の所有者を移動するコードは保守的に拒否する。
- Send/Share は組込み trait。プリミティブとスケジューラの識別ハンドルは共有可能。通常の集約値は Send、不変 snapshot は Share。FileHandle は Send ではない。`T:Send` / `T:Share` は型引数にも適用する。
- クロージャーは実際に参照する自由変数を捕捉する。Send は捕捉値から、Share は不変で共有可能な捕捉値から判定する。可変変数を捕捉したクロージャーは move で渡す。関数型だけでは捕捉情報を表せないため、関数引数側の Share 判定は保守的になる。
- タスク生成、チャネル送信、タスクの戻り値は独立したグラフを作る。クロージャー内の可変セルもコピーする。複数回 await した可変結果も別々の所有者になる。自由なグローバル変数はタスク生成時にコピーする。無関係な資源は捕捉しない。
- 転送は深さ 64 まで。循環グラフと資源を含む graph は実行時にも拒否する。静的な規則は完全な Rust の借用検査ではなく、字句スコープと明示 move を中心とする。

## 2. タスクの終了

`await Task<T>` は `Result<T,TaskError>`。T が Result のときは二層を維持する。

```rewind
enum TaskError {
    Cancelled,
    ChannelClosed,
    Deadlock(WaitGraph),
    BudgetExceeded(BudgetKind),
    Failed(Diagnostic),
}
```

WaitGraph は `description:String` を持ち、詳しい待機状態は debugger の tasks 表示にある。BudgetKind は `ExecutionSteps`、`TaskSteps`、`History`、`Other(String)`。Diagnostic は `code:String`、`message:String`、`causes:List<String>`。

TaskGroup の using スコープは正常終了時に子を join する。失敗時は子を cancel し cleanup を試す。未確認の子の失敗はスコープ終了や publish の前にエラーにする。`task.ignore()` / `task.detach()` は失敗を意図的に無視する宣言で、VM 終了後まで動くバックグラウンドタスクを作るものではない。await した結果は確認済みとして扱う。

取消しは次の命令の安全点で反映する。既に完了したタスクの結果は変更しない。停止中のタスクを cancel した場合は cleanup を LIFO で試す。元の失敗と複数の cleanup 原因を保持する。取消し自体にも cleanup 失敗がある場合は Failed(Diagnostic) として原因を残す。Channel の close が VM 命令として先に処理されれば ChannelClosed、先に完了した cancel は Cancelled となる。

## 3. 効果

```rewind
pub fn read(path:String) -> Result<String,FileError> effects {fileRead} {
    return File.readText(path);
}
```

公開関数には明示 effects が必要。非公開関数は推論できる。関数からの呼び出しを固定点まで伝播し、宣言集合を超える操作を拒否する。アプリケーションは到達する API の効果のみを必要とし、未使用 I/O API が同じライブラリにあっても純粋 API の利用に権限を要求しない。モジュールと署名付き package metadata は上限として検査する。library/async 内の publish は拒否する。

既知の関数別名は追跡する。型だけが分かる関数値、書き換え可能な関数値には全 10 効果の上限を要求する。generic trait 呼び出しは対応する trait の実装から保守的に伝播する。効果を隠すことはできないが、関数型の効果パラメータと単相化後の精密化はまだない。

## 4. 実行成果物

```sh
rewind update --root project
rewind build --root project --output program.json
rewind run-artifact program.json --root runtime-data --allow-effects output,tasks
rewind keygen private.seed
rewind sign-artifact program.json --key private.seed
rewind run-artifact program.json --root runtime-data --allow-effects output,tasks --verify-key PUBLIC_KEY
```

format 2 の成果物は可搬な型付き IR、bytecode、型シグネチャ、定数、効果、相対ソース位置、ソース/lock/API 文書のハッシュ、compiler 版を含む。外部のソース、manifest、依存ディレクトリがなくても実行できる。root は仮想 I/O のデータ領域として存在する必要がある。

ローダーは形式、compiler、内容ハッシュ、標準型の layout、参照、型・所有権・効果を検査する。信頼したコンパイラで IR を再コンパイルし、全命令と関数入口を照合することで、不正命令、ジャンプ、スタックの偽造を実行前に拒否する。文字列として保存された任意命令を実行しない。SHA-256 は内容の整合性、`--verify-key` は配布元の認証に使う。

上限はファイル 32 MiB、生成 payload 16 MiB、IR 式 10 万、関数 4096、モジュール 1024、命令 100 万。実行時の予算も適用する。generic は型付き template を含み、必要な instance を VM 内で生成する。

同じ入力の成果物は配置ルートに依存しない。内容ハッシュをキーに `.rewind/cache/` へ成果物を保持する。モジュールの解析結果も内容ハッシュでコンパイラのセッション内に再利用し、API 文書生成などでの再解析を省く。このメモリキャッシュは 128 モジュール、各ソース 128 KiB まで。ディスク上の任意 IR を信頼して取り込まない。型・効果検査は毎回行い、キャッシュを削除しても成果物は一致する。

## 5. パッケージと鍵

v0.4 の署名検査に加え、package metadata の `dependencies` を再帰的に解決する。取得元は manifest のローカルミラーで明示する。

```toml
[registry]
util = "file:vendor/util"
```

各推移依存にも `[dependency_signers]` と `[trust]` が必要。版、要求範囲、依存辺、効果、署名鍵、内容ハッシュを lock へ保存する。update はミラー上の版、制約に合う理由、前の lock との差分を stderr に表示する。複数候補から自動探索するレジストリではなく、一つの明示ミラーを選ぶ方式である。制約が合わなければ停止する。実行時のネットワーク取得はない。

manifest の最上位 `revoked = "old-key-id"` は失効鍵を拒否する。鍵更新は trust と signer の変更、再署名、明示 update で行う。失効情報を自動取得しない。keygen は OS の乱数で 32 bytes の seed を作り、既存ファイルを上書きしない。Unix では秘密鍵に mode 0600 を指定する。秘密鍵はリポジトリに保存しない。

artifact/trace/package の署名は別の用途識別文字列を使う。`sign-trace`、`verify-trace`、`verify-artifact` も提供する。

## 6. 型機能と標準ライブラリ

`impl<T:Bound> Trait for Container<T>`、関連型 `type Item = T;`、`Self::Item` を使える。関連型の定義はメソッドより前に書く。重複 impl は拒否する。

`for item in collection` は iter/next の反復へ展開する。List は値、Map は順序付きキー、String は Unicode scalar、Bytes は整数を走査する。組込み Iterator は取得時の snapshot とカーソルを保持し、checkpoint でカーソルを戻せる。ユーザーの iter/next メソッドも静的に解決する。

trait のデフォルト実装と動的 trait object はこの版では採用しない。[標準 API](stdlib-v0.5.md) に型署名と効果をまとめる。

## 7. 記録、秘密値、編集

```sh
rewind run --root project --record session.json
rewind test --root project --explore 100 --record failing.json
rewind replay failing.json --root project
rewind debug-session session.json --root project
rewind lsp --root project
```

失敗した run/test も実行結果、cleanup 原因、予算、スケジュール選択を記録する。探索で失敗した系列は --record で指定したファイルに保存し、その test を replay で再実行する。探索の出力は pending 件数を含み、予算による打ち切りと完了を区別できる。test 複数件の --record は最後に保存した一件を表す。

debug-session のコマンドは step、continue、checkpoint NAME、state、tasks、files、quit。ソースがある場合は記録の prefix を独立した VM に再生して命令ごとの状態を得る。Host 公開と記録ファイルの変更は行わない。ソースがない場合は記録された checkpoint/最終状態とイベントを表示できるが、任意命令の状態再構成はできない。files は書込み・削除、長さ、変更ページを示す。

LSP は stdio の Content-Length JSON-RPC。全文同期、保存前の構文・型・効果・所有権診断、補完、関数の定義参照、関数/変数の型表示を提供する。位置は UTF-16。文書は最大 128 件、各 512 KiB、メッセージ 1 MiB。rename、差分同期、コード修正は未実装。

`secret(T) -> Secret<T>`、`reveal(Secret<T>) -> T` を持つ。Secret を含む集約値とクロージャーは表示全体を伏せる。算術・比較・文字列結合の派生値も Secret を保つ。短絡論理と Secret の通常 API 操作には明示 reveal が必要。これは表示制御であり、reveal は明示的な秘密解除である。

秘密な環境観測は `--secret-env NAME` で指定する。記録には実行に必要な秘密を保存せず、再生時にも同じ指定と外部環境値が必要になる。Secret 型で後から包んでも、すでに通常観測として記録した環境値が遡って秘密指定されるわけではない。暗号化された記録は未採用。

## 8. 移行と検証

`rewind migrate --root project` は manifest の変更案と v0.5 の診断を表示する。`--write` はソースの検査が通った場合に language と lock を更新する。move や effects を意味を推測して自動挿入しない。旧 trace/compiler の不一致は理由付きで拒否し、新版での再記録を必要とする。

検証対象: 旧版の回帰、Frozen/move/借用/checkpoint、資源捕捉、クロージャーと戻り値の独立性、関数効果、generic impl/関連型/iteration、正常 join と未確認失敗、署名/改変、配置ルートに依存しない成果物、ソースなし実行、推移依存/失効、移行の preview、LSP の未保存文書、Host 公開しない debugger、Secret の派生集約値、失敗探索系列の replay、複数 cleanup 原因。

コマンドをまたぐモジュール単位の増分コンパイル、精密な関数型の効果、借用引数は実装済みとは扱わない。これらを含む改善案は [v0.6 提案](REWIND_v0.6.md) に記載する。
