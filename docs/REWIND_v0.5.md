## 1. 目的

v0.4 は決定的なタスク、チャネル、集合としての Checkpoint、署名付き依存、記録再生を備えた。次は、利用者が実行して初めて気付く制限を型検査で説明し、ライブラリとアプリケーションを配布できる言語へ進める。

優先順位:

| 優先 | 機能 | v0.4 からの改善 |
|---|---|---|
| 必須 | 所有権・不変 snapshot・タスク転送の型検査 | 資源やクロージャーの転送、凍結値の変更を実行前に診断する |
| 必須 | 型付きタスクエラー・構造化された cleanup 原因 | String 比較と二重 Result の処理を明確にする |
| 必須 | 関数ごとの効果と能力の伝播 | 未使用関数・同名メソッドまでまとめて要求する制限を減らす |
| 必須 | 検証済み実行成果物 | JSON 命令テンプレートから、配布・実行できる形式へ進める |
| 推奨 | generic impl・関連型・標準 Iterator | 再利用可能なコレクション・ライブラリを書くための表現を増やす |
| 推奨 | ソースマップ・LSP・対話デバッガ | エラー箇所とタスク間の因果関係を編集時に追跡する |

## 2. 所有権と共有の規則

### 2.1 型の区別

暫定案は、通常の可変コレクション T と `Frozen<T>` を分ける。`freeze(value)` は独立した深い snapshot を返し、Frozen の更新は型エラーにする。戻す場合は `thaw(snapshot)` で独立した可変コピーを作る。

```rewind
// 暫定構文
async fn count(values: Frozen<List<Int>>) -> Int {
    return values.len();
}
let values = List<Int>();
values.add(7);
let task = spawn count(freeze(values));
```

- `Send` はタスクへ転送できる型、`Share` は不変共有できる型を示す組込み trait とする。
- Int/String/Bytes などは Share。Frozen<T> は含む値が適切な場合に Share/Send。
- Channel/Task は VM 内の識別ハンドルとして共有できる。FileHandle は既定では転送不可。
- move は値の所有者を移し、以後の元変数の使用を拒否する。可変参照を複数タスクに残さない。
- クロージャーは実際の自由変数だけを捕捉し、Send/Share を捕捉値から計算する。無関係なグローバル資源によってタスク生成が拒否されないようにする。
- 借用はまず同一タスクの字句スコープ内に限定する。await をまたぐ可変借用と、借用値の Channel 送信は拒否する。

Checkpoint の復元後に有効な参照が別世代のオブジェクトを指さないよう、所有権・借用状態も保存する。v0.4 の実行時 snapshot 検査は移行期間に残す。

**完了条件:** 不正な更新、使用後 move、資源捕捉、await をまたぐ可変借用に、ソース位置と解決方法を示す。合法な転送と revert/resume が結果を保ち、既存コード用の互換モードでも実行時の防護が残る。

## 3. エラーと構造化されたタスク終了

暫定的に `TaskError` を標準 enum にする。

```rewind
// 暫定構文
enum TaskError {
    Cancelled,
    ChannelClosed,
    Deadlock(WaitGraph),
    BudgetExceeded(BudgetKind),
    Failed(Diagnostic),
}
```

`await Task<T>` は `Result<T,TaskError>` を返す。T 自体が Result の場合は、タスクの失敗と業務の失敗を区別できるよう二層を維持する。標準 helper による変換・flatten は、原因を失わない明示操作にする。

TaskGroup には正常終了時の join と失敗時の cancel-and-join を定義する。未確認の失敗を捨てるには明示的な detach/ignore を要求し、既定ではスコープの終了結果へ含める。cleanup の失敗は元エラーの下に原因列として残し、最後まで LIFO を試す。

取消しは cooperative な request と完了待機に分け、自分自身への取消しも次の安全点で扱えるようにする。チャネル close と取消しが同じイベントで競合した場合の優先規則を文書化する。

**完了条件:** match の網羅性検査、取消し、親の `?`/panic、予算超過、複数 cleanup 失敗を検証する。Host 公開前に子の終了結果を確定できる。

## 4. 関数単位の効果

```rewind
// 暫定構文
pub fn load(path: String) -> Result<String,FileError>
    effects {fileRead} {
    return File.readText(path);
}
```

関数シグネチャに効果集合を持たせ、呼び出し・関数値・trait メソッド・generic の型引数から伝播させる。純粋関数は空集合。実装型に応じて対象メソッドを確定し、同名の無関係なメソッドを混ぜない。

manifest とパッケージ metadata の効果は上限として残す。使用される API の必要効果を検査し、能力不足は「呼び出し元 → 関数 → 操作」の経路で表示する。環境変数名とファイルパスの能力の細分化は別段階とし、最初から複雑な権限ポリシーを導入しない。publish は引き続きアプリケーションの境界に限定する。

**完了条件:** 関数値・クロージャー・generic/trait 呼び出しで効果を隠せない。純粋 API の利用者に同じモジュール内の未使用 I/O API の権限を要求しない。

## 5. 成果物とパッケージ

### 5.1 実行形式

`rewind build` は型検査済みの bytecode、定数、必要な型 instance、効果、ソースマップ、依存・コンパイラの識別情報を持つ版付き成果物を生成する。`rewind run-artifact FILE` はソースなしでも検証して実行できるようにする。

ローダーは命令、ジャンプ先、スタック整合性、型表、宣言能力、長さと resource budget を検証してから VM に渡す。不明な版は拒否する。絶対パス・時刻を含めず、同じ入力の成果物と API 文書ハッシュは配置ルートやビルドマシンによらず一致させる。変更のないモジュールは内容ハッシュでキャッシュし、キャッシュを消しても同じ結果にする。

### 5.2 配布と信頼

ローカルミラーを維持し、任意の外部取得は VM 外の明示 fetch に分ける。レジストリはまず追加可能な取得元として定義し、実行時の自動取得は行わない。更新候補一覧、版選択の理由、推移依存の固定、鍵の更新・失効情報を扱う。署名済みでも効果・版・内容検査を省略しない。

鍵生成コマンドは安全な乱数を使い、秘密鍵ファイルを意図した場所にだけ作る。成果物と記録の署名をパッケージ署名と異なる用途のメッセージとして定義する。

**完了条件:** ソースなし実行、破損・改変・未知形式の拒否、異なる環境での byte 一致、鍵失効・推移依存・更新差分表示の試験を行う。ネットワーク停止中でも固定済み成果物を再実行できる。

## 6. ライブラリを作るための型機能

- `impl<T: Bound> Trait for Container<T>` と関連型を追加する。
- Iterator/IntoIterator の標準 trait と `for value in collection` を導入する。
- trait のデフォルト実装を検討する。impl の重複と選択を決定的に検査する。
- 数値・文字列・Bytes・コレクションの API を型署名、効果、失敗型まで揃えた標準文書として配布する。

型推論と単相化の予算は維持する。動的 trait object は必須に含めず、静的な関連型・generic impl の意味を先に確定する。

**完了条件:** 外部パッケージで汎用コレクションと Iterator を実装でき、境界不足・impl 重複に利用者のコード位置を示す。単相化の再帰と型拡張は予算内で停止する。

## 7. 診断、編集、再生

ソースマップは module ID と相対パス・行列を持ち、import したコードの実行時エラーも元ファイルへ戻す。LSP は補完、定義参照、型・効果表示、構文・型エラーを提供する。対話デバッガは保存済み記録で step/continue、Checkpoint の移動、タスク待機グラフ、変数と仮想ファイル差分を表示する。表示操作は Journal を消費しない。

記録にはスケジュール選択、Budget、実行結果、原因を含め、失敗した実行も再生できるようにする。探索で得た一つの選択系列を保存し、その系列と同じ観測だけを使って再現する。探索の上限到達と探索完了を区別する。

秘密データは型や表示方針を使って識別し、既知文字列の置換だけに依存しない。再生に必要な値は明示的な外部供給または暗号化された保存に分ける。表示用に除いた情報と実行用に必要な情報の違いを利用者へ示す。

**完了条件:** 観測・出力を増やさないデバッグ操作、失敗と探索系列の再生、秘密値を含む構造体・派生値の表示制御、源ファイルへ辿れる診断を試験する。

## 8. 互換性・工程・対象外

`language = "0.5"` で新しい所有権・効果・エラー規則を選ぶ。v0.1〜v0.4 のモードは保存し、移行コマンドは変更案を表示してから書き換える。lockfile と trace は形式番号を付け、互換な旧版を読むか、変換が必要な理由を診断する。旧版の署名検査を弱めない。

工程は、所有権・TaskError の小さなプロトタイプ → 型・効果検査と互換試験 → 成果物 verifier/loader → 標準 trait → 記録・編集ツールの順に進める。各段階で既存テストを維持する。工程を分割しても、未実装の項目を完了と記載しない。

通常 VM のネットワーク、DB、FFI、OS スレッド、子プロセス、GPU、実時間タイマーは引き続き対象外。外部取得ツールはプログラムの実行効果と分けて設計する。非同期スケジューラの OS 並列化や JIT はこの版の必須要件にしない。

実装前に決定する点:

1. Frozen と move/借用の具体的構文、資源の独占所有の表現。
2. TaskGroup の失敗集約型と detach の責任範囲。
3. 効果を持つ関数型・trait 型の表記と generic の効果パラメータ。
4. 成果物の安定形式、旧版変換、署名・鍵失効の運用。
5. 記録の暗号化・外部秘密供給と再生可能性の扱い。

この提案は v0.5 の実装済み機能を示すものではない。
