# REWIND の形式文法

この文書は REWIND 専用のエディタ（構文の色付け、補完、構文解析）を作る人に向けて、形式文法 [`rewind.ebnf`](rewind.ebnf) の読み方と使い方を説明します。言語の使い方は [言語リファレンス](../language-reference.md) にあります。

対象の版は 3.6.0 です。ここに書く内容は 2026 年 10 月時点の実装を動かして確かめたものです。

## 目的と使い方

正本は [`rewind.ebnf`](rewind.ebnf) です。字句の規則、型・パターン・式の規則、文・ブロック・宣言・ファイル全体（`Program`）の規則を、W3C 形式の EBNF で書いています。この文法が受理する入力は、実装の字句解析器 `lex()` と構文解析器 `Parser::program()` が受理する入力と一致します。ただし型検査などの意味の検査は含みません。

文法は、文章で書いただけの仕様ではありません。実装との突き合わせテストが受理と拒否の両方を確かめています。テストは `src/v2/grammar_check/` にあります。EBNF の読み込みと Earley 法の認識器（文法に曖昧さがあっても受理を判定できる方式）を自前で持ち、同じ入力を実装と文法の両方に通して結果を比べます。

次のコマンドで、テストを実行します。

```text
cargo test --release --bin rewind grammar_check
```

時間のかかる全件の検査は、`#[ignore]` にしてあります。次のコマンドで実行できます。

```text
cargo test --release --bin rewind grammar_check_full -- --ignored
```

テストが比べているものは、次のとおりです。

| 比べるもの | 内容 |
|---|---|
| docs の例 | `docs/` 以下の文書にある REWIND のコードのブロック |
| 標準ライブラリ | `libraries/` の `.rw` |
| fixtures | `tests/fixtures/` の `.rw` |
| examples | `examples/` の `.rw` の全件 |
| tests の埋め込み断片 | `tests/*.rs` の文字列に埋め込まれた REWIND のソース |
| 受理と拒否の例 | `tests/grammar/accept/*.rw`（両方が受理するはずの例）と `tests/grammar/reject/*.rw`（両方が拒否するはずの例）。各ファイルの先頭行に、何を確かめる例かを書いてあります |
| トークン変異 | 上の入力から、トークンを 1 つ消す、別の語に替える、2 か所を替えるなどして作った入力。変異の入力でも、実装と文法の結論が一致すること |

字句の検査では、`lex()` が出すトークン列と、文法の字句規則が切り出すトークン列も比べます。

次の 2 つは、文脈に依存するので文法では表せず、既知の差として扱っています。

- raw 文字列の複数行の形で、本文の各行が閉じの引用符の行と同じ字下げで始まること。
- `0x`、`0b`、`0o` の整数が、値として u64 に収まること。

## 表記の約束

表記は W3C の EBNF です。`::=` で規則を定義します。

| 書き方 | 意味 |
|---|---|
| `UPPER_CASE` | 字句規則。小文字を含まない名前です。1 文字ずつの列に対して働きます |
| `CamelCase` | 構文規則。トークンの列に対して働きます |
| `'abc'` | リテラル。構文規則の中では、記号や語のトークンを表します |
| `[a-z]`、`[^"\\]` | 文字クラス。`[^...]` は否定です |
| `#x41`、`[#x41-#x5A]` | 16 進数で書いたコードポイント。範囲も書けます |
| `A - B` | 差。A に当たる入力のうち、B に当たるものを除きます |
| `A?`、`A*`、`A+` | 0 回か 1 回、0 回以上、1 回以上 |
| `A \| B` | 選択 |
| `( ... )` | まとまり |
| `/* ... */` | コメント |
| `[ ns: X ]`、`[ nf: X ]` | 先読みの注釈。次の節で説明します |

構文規則の終端には、字句規則の名前（`IDENT`、`INT`、`FLOAT`、`STRING`、`RAW_STRING`、`SYMBOL`）と、リテラルを使います。リテラルの `'if'` は本文が `if` の名前（IDENT）のトークンに当たります。予約語は字句の段階では区別せず、すべて IDENT として切り出されます。

## 先読みの注釈

EBNF の通常の記法では書けない選択を、先読みの注釈で書いています。どちらも長さ 0 で、入力を進めません。

| 注釈 | 意味 | 使う場所 |
|---|---|---|
| `[ nf: X ]` | 直後の 1 文字が X でない | 字句規則。たとえば `DEC_INT ::= DEC_RUN [ nf: [_eE] ]` |
| `[ ns: X ]` | 次のトークンが X でない | 構文規則。たとえば `Name ::= [ ns: 'begin' ] IDENT` |

入力の終わりでは、どちらの注釈も成り立ちます。`rewind.ebnf` の冒頭のコメントは、どちらも同じ意味で使えると書いています。実装では、文法を読み込む `ebnf.rs` が両方の注釈を構文木に取り込み、認識器の `earley.rs` が点が注釈に来た時点で次の 1 トークンを見て判定します。

エディタ側での扱いは、次のとおりです。

- 色付けだけが目的なら、構文規則の注釈は無視できます。色付けでは、字句の規則とキーワードの一覧があれば足ります。
- 字句規則の `nf` は無視できません。最長一致で名前や数を切るときの条件になるからです。たとえば `1else` が字句の誤りになるのは、数の直後に `e` が来ると `nf` が失敗して、どの数の規則も当たらなくなるためです。
- 構文解析器を作るときは、注釈を先読みの条件として実装してください。LL(1) や手書きの再帰下降では、次のトークンを見て分岐する処理がそのまま `ns` になります。
- `ns` の多くは、名前の位置から特別な語を除くために書いてあります。`[ ns: 'if' ]` は、式の先頭の名前が `if` ではないことを表します。

## 字句の約束

### 最長一致

字句の規則は最長一致で入力を切ります。位置ごとに、TOKEN か SKIP のどちらかで受理できる最も長い接頭辞を取ります。

- TOKEN は、`IDENT`、`INT`、`FLOAT`、`STRING`、`RAW_STRING`、`SYMBOL` です。
- SKIP は、空白（`WHITESPACE`）と、行コメント、ブロックコメントです。SKIP は捨てます。
- TOKEN と SKIP が同じ位置で受理できることはありません。
- どの TOKEN にも SKIP にも当たらない入力は、字句の誤りです。

2 文字の記号は 15 個だけです（`== != <= >= && || += -= *= /= %= -> => :: ..`）。`>>` と `<<` はありません。`>` を 2 つ並べると、`>` のトークンが 2 つになります。

### `>=` の分割

`let xs: List<Int>= [1];` のように、型引数を閉じる `>` のすぐ後ろに `=` が続くと、字句解析器は `>=` を 1 つの記号として切ります。構文解析器は、型引数を読み終えるとき、`>=` の先頭の `>` だけを食べて、残りの `=` を次のトークンとして扱います。

このため、文法では `>=` を常に 2 つのトークン（`GE_FIRST` と `GE_SECOND`）に分けて扱っています。比較演算子の `>=` は `GE_FIRST GE_SECOND` と書きます。型引数を閉じる `>` は、`GE_FIRST` も含めて、text が `>` のトークンに当たります。間に空白のある `> =` は、種別が SYMBOL の別々のトークンなので、比較演算子になりません。

エディタが構文解析器を持つなら、同じ分割をするか、型の文脈で `>=` を見たときに分けてください。色付けだけなら気にしなくてかまいません。

### raw 文字列の引用符

raw 文字列は、N 個（3 個以上）の引用符で開き、ちょうど N 個の引用符で閉じます。本文には、N 個より短い引用符の連なりを置けます。「開きと閉じの個数が同じ」という条件は、文脈自由文法では書けません。そこで文法は、N が 3 から 6 までの場合を、規則（`RAW3` から `RAW6`）に展開して近似しています。

- 7 個以上の引用符でも、実装は raw 文字列として受理します。この文法は受理しません（既知の差）。
- 引用符 6 個の `""""""` は、空の raw 文字列ではなく、閉じていない raw 文字列として誤りになります。
- 形は 2 つあります。開きの直後に空白と改行だけが続くときは複数行の形です。そうでなければ 1 行の形で、閉じまで改行を含められません。

エディタで raw 文字列を色付けするときは、開きの引用符の個数を数えて、同じ個数の連なりを探す処理を、字句規則の外に実装してください。

### 文字列のエスケープ

字句の段階では、`\` の次の 1 文字を何でも読み飛ばします。使えるエスケープ（`\n \r \t \" \\ \0 \u{...}`）かどうかは、構文解析のときに検査されます。色付けでは、`\` で始まる 2 文字を 1 つのエスケープとして扱えば足ります。

## 曖昧さの解消

構文規則の文法だけでは曖昧になる箇所を、構文解析器の選び方で決めています。`rewind.ebnf` の構文の節の冒頭に、文章で書いてあります。要点は次のとおりです。

- 名前の直後の `<` は、まず型引数として読みます。`>` で閉じ、直後が `(` か `::` のときだけ型引数になります。そうでなければ位置を戻し、`<` を比較演算子として読みます。
- `X::Y` のように `::` を含む名前の直後の `{` は、必ず名前つき構築の `{` になります。
- 式の先頭の `|` と `||` は、クロージャの始まりです。`||` は式の途中（中置）では論理和です。
- クロージャの短い形 `|a| 式` の本体は、できるだけ長い式をとります（右に伸びます）。
- `&` の直後の `mut` は、必ず `&mut` の一部になります。
- 二項演算子は左結合です。優先順位は低い順に `||`、`&&`、`== !=`、`< <= > >=`、`+ -`、`* / %` です。
- 後置（`::`、`[ ]`、`.数`、`.名前`、`.名前<T>(`、`( )`、`?`）は、優先順位に関係なく必ず結合します。
- `{` がマップかブロックかは、`{` の次が `}` でなく、その次が `:` のときだけマップです。これだけは 1 トークンの先読みでは書けず、マップの最初のキーを 1 トークンの形に限る（`MapKey1`）ことで表しています。
- 式のブロックの中で `if`・`match`・`{` で始まる文は、まず式として読みます。式として読めたあとの失敗では、文として読み直しません。

## 実装の癖

次の癖は、実装が正で、文法がそのまま写したものです。エディタを作るときに、現状の挙動として知っておいてください。

「（修正済み。番号は変えない）」と書いた項目は、すでに直った癖です。以前の挙動を知っておく必要がある場合のために、番号と説明を残しています。

表で「不具合に見える」と書いた項目は、仕様として決めたものではありません。現状の挙動で、修正される可能性があります。修正されると、その入力は受理か拒否のどちらかに変わります。エディタは、こうした入力の扱いに強く依存しないようにしてください。

確かめた例は、`fn main() -> Int { ... }` の中に書いて `rewind run` で動かした結果です。結果の欄の「エラー」は、実行前に拒否されたことを表します。

### 実装の挙動に起因する拒否

以前は、`if x == E::A { ... }` と `match E::A { ... }` が、`E::A {` を名前つき構築と読むために誤りになっていました。今は、`{` の次が `名前 :` か `}` のときだけ構築と読み、`if`・`while`・`match`・`for` の条件部（括弧などに囲まれない位置）の空の `{ }` は、構築ではなくブロックと読みます。そのため `if x == E::A { Out.println("a"); }` や `match E::A { ... }` は、括弧なしで動きます。条件部の最上位で `E::A {}` を空の構築として使いたいときは、`(E::A {})` のように括弧で囲んでください。

エディタが補完や診断を出すときは、この規則（条件部の中かどうか）を、構文の解釈に入れてください。

## 4.0.0 で変わったこと

[言語リファレンスの付録 B](../language-reference.md#400-の変更)に、4.0.0 の変更が書いてあります。文法に関係する主な点は次のとおりです。

- 言語 4.0.0 では、宣言・制御・チェックポイント・式の約 45 語が予約語になり、名前として使えません。ただし、この文法（`rewind.ebnf`）は予約語を特別に扱いません。文法は、予約語を名前として使う書き方も構文としては受理します。拒否するのは、構文解析のあとに行う検査で、言語が 4.0.0 のときだけです。エディタは、構文の木を作ったあとで、名前の位置にある予約語に警告を出してください。
- 言語 4.0.0 では、`null` リテラルを書けません。文法は `null` を名前の一つとして受理します。`null` の検査も、予約語の検査と同じ段階で行います。
- REWIND 4 は、`language` が 3.0.0 未満の指定を受け付けません。
- どの言語でも、通常の文字列リテラルの中の改行は LF になります。文法は、ソースの文字をそのまま受理します。

`tests/grammar/` の `accept/kw_let_if.rw`、`accept/kw_name_field.rw` などは、キーワードを名前に使う例です。先頭行に「現状の挙動。4.0.0 で予約語になる予定。」と書いてあります。構文としては今も受理するので、受理の例に置いています。実際の拒否は、構文解析のあとの検査で行います（言語 4.0.0 のとき）。

## 色付けに使うキーワードの一覧

構文解析器（`src/v2.rs` の `Parser`）が文脈で見ている語を、種類ごとにまとめます。言語 3.x では名前として使えてしまう語（`begin` 以外）も含みます。

言語 4.0.0 で予約語になる語は、言語リファレンスの 3.2 節の表にある約 45 語です。次の表の「4.0.0 の予約語」の列に、その印を付けました。`None` は、variant の名前に使えるように、予約語にしていません。

| 種類 | 語 | 4.0.0 の予約語 | 補足 |
|---|---|---|---|
| 宣言 | `fn` `struct` `record` `enum` `trait` `impl` `type` `const` `import` `as` `pub` `private` `async` `mut` | はい | `mut` は `&mut` の中の語。`private` は構造体の欄の修飾 |
| 制御 | `if` `else` `match` `while` `for` `in` `break` `continue` `return` `let` `var` `defer` `using` | はい | `for` は `impl 型 for 型` でも使う。`let` は `if let` と `while let` でも使う |
| チェックポイント | `commit` `revert` `resume` `drop` `publish` `branch` `runtime` `external` `begin` | はい | `begin` は最初のチェックポイントの予約名。言語 3.x でも名前にできない唯一の語 |
| 式 | `move` `spawn` `await` `true` `false` `None` `null` | `None` 以外ははい | `move` は前置演算子としても、`capture move` の中でも使う。`None` は名前に使える |
| 修飾語 | `value` `capture` `borrow` `force` `live` `fresh` `test` `where` `effects` `captures` | いいえ | 文脈によって意味が決まる語のまま残る。`capture value\|move\|borrow`、`publish force`、`external live\|fresh`、`test fn`、`where` 節、`effects { }`、`captures { }` |
| 設定名 | `historyMemory` `historyStorage` `spillThreshold` `executionSteps` | いいえ | `runtime { ... }` の中だけ。単位は `KB` `KiB` `MB` `MiB` `GB` `GiB` |
| 捕捉の旗 | `Send` `Share` | いいえ | `captures { Send, Share }` の中だけ |

`freeze`、`thaw`、`panic`、`assert` や、`Some`、`Ok`、`Err` は、キーワードではなく、関数や名前です。色付けを分けたいときは、標準ライブラリの名前として扱ってください。

上の表のうち、修飾語の `test` は直後が `fn` のときだけ、`async` は関数宣言の先頭でだけ働きます。色付けでは、位置を見て切り替えると、名前として使った場合を誤って塗らずに済みます。
