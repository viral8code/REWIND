# REWIND 4.1.0

オセロ（GUI）を書いた利用者からの報告をもとに、実行予算の数え方と GUI を直したバージョンです。言語の規則は変わりません。4.0.0 のプログラムは、そのまま動きます。

## 追加

- `runtime { nativeWork = N; }` で、ネイティブ処理量の上限をソースに書けます。これまでは `--native-work` でしか変えられず、「ソースだけで完結する」プログラムを作れませんでした。実行する側が `--native-work` を指定しているときは、ソースの値はそれより小さくすることだけができます。
- プロファイルに、ごみ集め（GC）の行 `<gc>` が出ます。以前は、たまたま実行中だった関数の費用として数えられていました。

## 直したこと

- 確保を繰り返すと、ネイティブ処理量が多く減っていました。GC は 256 回の確保ごとに、生きている値のすべてをたどって費用を数えていたためです。次の GC まで待つ確保の数を、前回たどった量（256〜65,536）にしました。生きている値が多くても、確保 1 回あたりの費用は一定です。
- 数や真偽値の引数が、1 つあたり 9 ほどの費用を使っていました。1 にしました。`record` の生成や、タプルを返す関数の呼び出しは、約 19 から約 3 になりました。
- `List` の `get`、`set`、`pop` は、要素の大きさの分だけ費用を使っていました。64 バイトごとに 1 にしました。
- 画面の描画（`gui.present`）の費用を、ウィジェット 1 つあたり約 2,000 から約 100 にしました。GUI の権限（`gui`）があるときの、ネイティブ処理量の既定値は 256,000,000 です。権限がないときは 1,000,000 のままです。
- Windows で最大化したウィンドウが、次の `present` で元の大きさに戻されていました。最大化している間は、View の寸法に合わせません。

## まだ対応していないこと

- 一時的な値を借用する書き方（`render(&List<Int>())`）。
- 整数の `match` のジャンプテーブル、ビット演算（`&`、`|`、`<<`、`>>`）。
- インタプリタ自体の速度。
- 円や塗りつぶしの描画、タイマー、`setBounds`、GUI の `--record` の既定の上限（`--record-mode compact` で避けられます）。

詳細は[言語リファレンスの付録 B](../language-reference.md#410-の変更)を参照してください。
